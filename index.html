How I build AI products

Models propose. Code decides.

Both of my multi-agent products follow the same five rules. They come from one question: where is the model allowed to be creative, and where must its output be checked?

  • Split work by risk

    LLM agents generate content. Deterministic code checks policy, facts and amounts.

  • Fail closed

    If output can't be verified, a human reviews it. Users never see the unverified version.

  • Bounded autonomy

    Every retry and revision loop has a hard cap, then escalates.

  • Evals are release gates

    Safety metrics must be exactly zero to ship. One fabrication fails the build.

  • Observable by default

    Every agent step is traced and every action is audited.

The problem

How it works

LLM model generatesCode deterministic checkHuman user decides
  1. Code
    Input guardrailsUnusable input is blocked with a reason, before any model call. Prompt injection and personal data are stripped.
  2. LLM
    Analyzer → TailorReads the posting, then rewrites bullets toward it. Each tailored bullet links back to its source bullet.
  3. Code
    CriticThe only verifier that can block. Each bullet must match one original (80%+ word overlap), add no new numbers, and claim no more ownership than the source. One retry, then fail closed.
  4. LLM
    Reviewer (advisory), Coach, Cover LetterFlags subtle exaggeration, names honest skill gaps, and drafts a letter with its own checker.
  5. Human
    Candidate reviewsOutput is ok, needs_human (résumé withheld) or blocked (with the reason).

Bugs the evals caught

FailureWhy it slipped throughFix (each with a regression test)
"Supported" → "Led"One changed verb still scored 90% word overlapOwnership-verb tiers, plus blocked scope words like "entire"
Nouns read as verbsVerb check scanned every wordCheck the opening verb and any verb the rewrite adds
Letter matched wrong bulletGeneric shared words created false matchesCompare each sentence only to its single closest bullet
"Java" matched "JavaScript"Substring skill matchingWhole-skill matching, now covered by an eval case

Key product decisions

  • Code verifies, not a model

    A model checking a model shares its blind spots. The Critic is deterministic, so its behaviour is predictable and testable.

  • No résumé is better than a wrong one

    If no draft passes after one retry, the user gets a reason instead of a résumé.

  • Rules gate, AI advises

    The AI Reviewer stays advisory until 100 labelled bullet pairs show its precision.

Next milestone

Grow the live eval set to 100+ real résumé and posting pairs, then a 100-user beta. Go/no-go gate: zero fabrications reached a user.
